# Server Logging Design

**Date:** 2026-05-24  
**Status:** Approved

## Problem

The server produces almost no logs. A "run now" request that failed due to a web search tool limit
returned a 503 to the user with no trace in `journalctl` beyond the access log line. There was no
way to know what Claude returned, what the failure content was, whether a credit was deducted, or
what step actually went wrong.

## Goal

Instrument the full server-side flow so any issue — API errors, tool failures, parse failures,
credit deductions, email sends — can be diagnosed from `journalctl` in seconds.

---

## Approach: Standard Python logging + request trace IDs

- **No new dependencies.** Uses stdlib `logging` and `contextvars` only.
- **Plain text format** readable directly in `journalctl -f`.
- **Per-request trace ID** (`req_id`): a short random hex token (e.g. `a3f2b1`) generated by
  middleware and stored in a `contextvars.ContextVar`. Every log line emitted during that request
  includes the ID. `grep a3f2b1` in journalctl gives the complete trace for one request.
- **Log level:** `INFO` for normal flow, `WARNING` for handled anomalies (search failures, parse
  errors), `ERROR` for unexpected exceptions and system faults.

---

## Architecture

### 1. Logging config (`web/logging_config.py`)

A new module that owns logging setup:

```python
import logging
import contextvars

_req_id_var: contextvars.ContextVar[str] = contextvars.ContextVar("req_id", default="-")

def get_req_id() -> str:
    return _req_id_var.get()

def set_req_id(value: str) -> contextvars.Token:
    return _req_id_var.set(value)
```

A custom `logging.Formatter` reads `get_req_id()` and injects it into every log record.

Format:
```
[LEVEL]  module  event  req_id=xxxx key=value key=value
```

Example:
```
[INFO]    queries  run_query_start   req_id=a3f2 query_id=fa097f74 user=irldavem@gmail.com credits=12
[INFO]    queries  api_call          req_id=a3f2 model=claude-sonnet-4-6
[INFO]    queries  api_response      req_id=a3f2 stop=end_turn blocks=text,tool_use,tool_result,text
[WARNING] queries  search_failure    req_id=a3f2 content="A live web search could not be completed..."
[INFO]    queries  run_query_done    req_id=a3f2 answer=NO search_failed=true credit_deducted=false
```

`logging.basicConfig` is called once in `main.py` at import time. Level: `INFO`.
Uvicorn's own access logs continue to work alongside this — no conflict.

### 2. Request middleware (`main.py`)

A FastAPI middleware added before the security-headers middleware:

```python
@app.middleware("http")
async def request_logging(request: Request, call_next):
    req_id = secrets.token_hex(4)   # 8-char hex, e.g. "a3f2b1c0"
    token = set_req_id(req_id)
    t0 = time.monotonic()
    logger.info("request_start method=%s path=%s req_id=%s", request.method, request.url.path, req_id)
    response = await call_next(request)
    ms = int((time.monotonic() - t0) * 1000)
    logger.info("request_done status=%d duration_ms=%d req_id=%s", response.status_code, ms, req_id)
    _req_id_var.reset(token)
    return response
```

### 3. Instrumented events per module

#### `web/routers/queries.py` — `run_query_now`

| Event | Level | Key fields |
|---|---|---|
| Run started | INFO | `query_id`, `user` (email), `credits` |
| Anthropic API call | INFO | `model`, `query` (first 60 chars) |
| API response received | INFO | `stop_reason`, `block_types` (comma-separated list of block type names) |
| Web search failure detected | WARNING | `content` (raw failure text from the tool_result block) |
| No text block in response | WARNING | `block_types` |
| JSON parse failure | WARNING | `raw` (truncated to 200 chars) |
| Credit deducted | INFO | `credits_remaining` |
| Email sent | INFO | `to` |
| Email send failure | ERROR | `exc` |
| Run complete | INFO | `answer`, `search_failed`, `credit_deducted` |
| Exceptions from Anthropic SDK | ERROR | `exc` |

#### `web/routers/queries.py` — `validate_description`

| Event | Level | Key fields |
|---|---|---|
| Pre-guard rejection | INFO | `reason` |
| LLM call | INFO | `model`, `description` (first 60 chars) |
| LLM result | INFO | `valid`, `feedback` |
| JSON parse failure from LLM | WARNING | `raw` |

#### `web/runner.py` — sequential and batch runners

Replace all `print()` calls with `logger` calls at equivalent levels. Add the same API-call
and search-failure events as `run_query_now` so the scheduled runner is equally traceable.
Runner does not have HTTP request context so no `req_id` — that field will be `-` (the default).

| Event | Level | Key fields |
|---|---|---|
| Runner start | INFO | `query_count`, `mode` (sequential/batch) |
| Per-query check start | INFO | `query_id`, `user`, `label` |
| API call | INFO | `model` |
| API response | INFO | `stop_reason`, `block_types` |
| Search failure | WARNING | `query_id`, `content` |
| No text block | WARNING | `query_id` |
| JSON parse failure | WARNING | `query_id`, `raw` |
| Answer | INFO | `query_id`, `answer` |
| Email sent | INFO | `query_id`, `to` |
| Email failure | ERROR | `query_id`, `exc` |
| Credit deducted | INFO | `query_id`, `credits_remaining` |
| Batch submitted | INFO | `batch_id`, `count` |
| Batch poll | INFO | `batch_id`, `status` |
| Batch timeout | ERROR | `batch_id`, `timeout_minutes` |

#### `web/routers/auth.py`

| Event | Level | Key fields |
|---|---|---|
| Magic link requested | INFO | `email` |
| Magic link verified (success) | INFO | `email` |
| Magic link invalid/expired | WARNING | — |
| Session created | INFO | `user_id` |
| Session deleted (logout) | INFO | `user_id` |

#### `web/routers/billing.py`

Already partially instrumented. Add:

| Event | Level | Key fields |
|---|---|---|
| Checkout session created | INFO | `user_id`, `package`, `credits` |
| Webhook received | INFO | `event_type` |
| Credits added | INFO | `user_id`, `credits`, `total` (already exists) |

## What is NOT logged

- **Session tokens, magic link tokens, passwords** — never.
- **Full query text** in API call logs — truncated to 60 chars to avoid log spam.
- **Full API response text** — only metadata (stop reason, block types). Full text only on
  WARNING/ERROR (parse failure raw, search failure content).
- **Request bodies** — not logged at the middleware level (could contain PII).

## How to use

```bash
# Follow all logs
sudo journalctl -u notifai-web -f

# Trace a single request end-to-end
sudo journalctl -u notifai-web | grep req_id=a3f2b1c0

# See all web search failures
sudo journalctl -u notifai-web | grep search_failure

# See all errors
sudo journalctl -u notifai-web -p err

# Follow the daily runner
sudo journalctl -u notifai-runner -f
```
